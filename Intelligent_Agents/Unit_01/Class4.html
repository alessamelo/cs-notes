Reinforcement Learning — Policy, Reward and Value Functions

← Back to Intelligent Agents

1. Reward

The reward is the immediate feedback received by the agent after taking an action.

At time t, the agent receives a reward:

Rt

The reward tells the agent how desirable or undesirable the immediate outcome was.

Reward = immediate feedback. It tells the agent what happened after an action.

The reward function is part of the environment and defines what the agent should try to maximize.

2. Return

The return is the total accumulated reward from a particular point in time into the future.

Without discounting, the return can be written as:

Gt = Rt + Rt+1 + Rt+2 + ...

Therefore, the return contains both the present reward and the future rewards.

Reward: what the agent receives now.
Return: accumulated reward from now into the future.

3. The Problem with the Return

In a continuing task, the sequence of rewards can potentially be infinite:

Gt = Rt + Rt+1 + Rt+2 + ...

If rewards continue forever, the total return may become infinite or fail to converge.

Reinforcement Learning therefore commonly uses a discount factor, represented by γ (gamma).

4. Discount Factor γ

The discount factor determines how much importance is given to future rewards compared with immediate rewards.

The discounted return is:

Gt = Rt + γRt+1 + γ2Rt+2 + γ3Rt+3 + ...

The current reward is not discounted. Future rewards are multiplied by increasing powers of γ.

Reward Discount
Rt 1
Rt+1 γ
Rt+2 γ²
Rt+3 γ³

Usually:

0 ≤ γ < 1

A smaller γ makes the agent more focused on immediate rewards. A value closer to 1 makes the agent consider future rewards more strongly.

Gamma helps control the contribution of future rewards and, for continuing tasks, helps ensure that the return converges.

5. Recursive Definition of Return

The return can also be expressed recursively:

Gt = Rt + γGt+1

This equation says that the return at time t is composed of:

Return = Present reward + Discounted future return

This recursive relationship is fundamental to many RL algorithms.

6. Policy

A policy defines how an agent chooses actions based on the current state.

A policy maps a state to an action or, in the stochastic case, to a probability distribution over possible actions.

Deterministic Policy

A deterministic policy always chooses the same action for a given state:

a = π(s)

Stochastic Policy

A stochastic policy assigns probabilities to the possible actions:

π(a | s) = P(At = a | St = s)

This means:

π(a | s) is the probability that the agent takes action a when it is in state s.

For every state s ∈ S and action a ∈ A, the policy determines how likely that action is.

7. Policy vs. Value Function

Concept Main Question Output
Policy "What should I do now?" An action or probability distribution over actions.
Value Function "How good is this situation?" A number representing expected future return.
Policy → decision.
Value function → evaluation.

8. Value Functions

The goal of modeling RL using MDPs is to find a policy that maximizes the expected cumulative reward while interacting with the environment.

A value function measures the expected return when an agent follows a particular policy.

There are two main value functions:

  • State-value function V
  • State-action value function Q

9. State-Value Function V

The state-value function measures the expected return starting from a state s and then following policy π.

Vπ(s) = Eπ[Gt | St = s]

Expanding the return:

Vπ(s) = Eπ [ Σk=0∞ γkRt+k | St = s ]

The state-value function therefore answers:

"If I am currently in state s and follow policy π, how much reward do I expect to receive in the future?"

10. State-Action Value Function Q

The state-action value function evaluates a state together with a specific action.

Qπ(s,a) = Eπ[Gt | St = s, At = a]

Expanded:

Qπ(s,a) = Eπ [ Σk=0∞ γkRt+k | St = s, At = a ]

The Q function answers:

"If I am in state s, take action a, and then follow policy π, how much reward do I expect to receive?"

The name Q-function comes from "quality": it measures the quality of taking an action in a particular state.

11. GPS Analogy

A GPS system provides a useful analogy for understanding the difference between policy and value functions.

Policy

The policy is similar to the GPS giving you directions:

"Turn left here. Continue straight. Then turn right."

It tells you what action to take.

Value Function

The value function is similar to estimating the quality of your current route, such as the expected travel time or likelihood of successfully reaching the destination.

It tells you how good the current situation is with respect to future outcomes.

12. Expected Value

The word expected means that the value is calculated by considering possible future outcomes and their probabilities.

In a stochastic environment, different outcomes can occur. The expected return is therefore a probability-weighted estimate of the possible returns.

13. Connection to Q-Learning

Q-learning is based on the Q-function. Instead of only evaluating states, it evaluates the quality of taking particular actions in particular states.

Q(s,a) → How good is it to take action a in state s?

The agent can use these values to select actions with high expected future reward.

14. Class Activity: Policy or Value Function?

Reinforcement Learning is not limited to games such as chess or Go. The same concepts can be applied to real-world problems.

The following examples distinguish between the Policy and the Value Function.

Case Study 1: Autonomous Delivery Drones

In logistics, drones must navigate from a warehouse to a customer's location.

Policy: The control system decides how much to tilt the rotors, when to increase speed, and how to steer around obstacles.

Value Function: Evaluates the quality of the drone's current state. For example, a drone with a clear path, sufficient battery, and good altitude may have a high value.

Decision Point: A drone calculates that moving to a higher altitude increases the probability of a safe arrival by 15%.

This calculation is primarily a value-related evaluation because it estimates the quality or expected future outcome of the state/action choice. The eventual decision to actually move upward is made by the policy.

Case Study 2: E-Commerce Recommendation Engines

Online stores can use RL to increase customer engagement and maximize long-term customer value.

Policy: Decides which product should be displayed next based on the customer's current state and history.

Value Function: Estimates the total future reward, such as the expected customer lifetime value, from the current state.

Decision Point: The system chooses to show wool socks because the user has added hiking boots to their cart.

The choice of what product to show is a policy decision.

Case Study 3: Smart Power Grids

A smart grid must balance electricity generated from wind, solar, batteries, and traditional power plants.

Policy: Makes real-time decisions such as: "Store 50 MW in the battery" or "Release energy to the grid."

Value Function: Evaluates the long-term quality of the current grid state based on expected stability, costs, and future demand.

Decision Point: The system evaluates a grid with full batteries during an approaching storm as a high-value state because it increases the probability of maintaining stability.

This evaluation is performed by the value function.

15. Summary

Concept Meaning
Reward Rt Immediate feedback received after an action.
Return Gt Accumulated discounted future rewards.
Gamma γ Controls how strongly future rewards are discounted.
Policy π Determines which action to take in a state.
Vπ(s) Expected return from state s while following policy π.
Qπ(s,a) Expected return from state s after taking action a and subsequently following policy π.
Core distinction:

Reward → What did I receive immediately?
Return → What total reward will I receive from here onward?
Policy → What should I do?
Value function → How good is this state?
Q-function → How good is this action in this state?
