1. Review

Reinforcement Learning (RL) comes from ideas related to Dynamic Programming.

One important RL algorithm is Q-learning.

2. Common Reinforcement Learning Terms

Episodic vs. Continuing Tasks

  • Episodic task: the interaction has a defined beginning and end.
  • Continuing task: the interaction does not have a terminal state and can continue indefinitely.

Stochastic vs. Deterministic Tasks

  • Deterministic: the same state and action always produce the same result.
  • Stochastic: the same state and action can lead to different outcomes according to some probability distribution.

Model-Free vs. Model-Based RL

Model-free RL: the agent does not explicitly know the environment's transition dynamics or reward model. It learns through interaction and trial-and-error.

For example, the agent does not have an explicit function describing how the environment changes after each action.

Model-based RL: the agent has or learns a model of the environment's dynamics. The model describes how actions affect future states and rewards.

Different algorithms can then use this model to plan future actions.

3. Exploration vs. Exploitation

A fundamental challenge in RL is deciding whether the agent should explore new actions or exploit actions that are already known to work well.

Strategy Meaning
Exploration Try new actions or visit new states to learn more about the environment.
Exploitation Use actions that have already demonstrated good results.

The objective is to maximize cumulative reward while finding a good balance between exploration and exploitation.

4. Credit Assignment Problem

The credit assignment problem occurs when the agent receives a reward after performing a sequence of actions and must determine which actions were responsible for that reward.

  1. Identify the actions that may have contributed to the reward.
  2. Analyze the outcomes statistically.
  3. Assign credit to the actions that contributed to success.
  4. Adjust the agent's policy based on this information.

Example: Atari

Suppose the objective in an Atari game is to break as many blocks as possible.

A good reward function should encourage behavior that actually helps the agent complete the game rather than behavior that only produces a short-term reward.

Reward function design is critical. A poorly designed reward function can cause unexpected behavior.

Example: CoastRunners

In the Atari game CoastRunners, a reward function that only rewards hitting certain objects can cause the agent to repeatedly perform the same action instead of completing the race.

This illustrates the importance of designing rewards that correctly represent the actual objective of the task.

5. Generalization

An RL agent acquires knowledge through interaction with an environment.

A good agent should be able to apply what it has learned to new situations, not simply memorize the situations encountered during training.

Therefore, it is important to evaluate whether the learned policy produces good results in environments or situations different from those used during training.

7. Markov Decision Process (MDP)

A Markov Decision Process (MDP) is a mathematical framework used to model sequential decision-making problems under uncertainty.

The agent does not have complete certainty about what will happen after taking an action.

An MDP can be represented as:

MDP = (S, A, P, R)

The main objective is to find a policy that maximizes the expected cumulative reward.

8. Components of an MDP

States — S

A state represents the current situation of the environment.

Actions — A

The set of all possible actions that the agent can take.

Transition Model — P

The transition model describes how the environment moves from one state to another after an action.

Because the environment may be stochastic, the transition is represented by a probability distribution:

P(s' | s, a)

This means the probability of transitioning to state s', given that the agent is currently in state s and takes action a.

Reward Function — R

The reward function specifies the reward or cost associated with taking an action in a particular state.

R(s, a)

The reward provides feedback to the agent about the quality of its decisions.

Policy — π

A policy specifies how the agent chooses actions based on the current state.

π(a | s)

This represents the probability of selecting action a when the agent is in state s.

9. Markov Property

Not every sequential decision problem can automatically be modeled as an MDP. The environment must satisfy the Markov property.

The future state is independent of the past given the present state and action.
P(St+1 | St, At) = P(St+1 | St, At, St-1, At-1, ...)

In other words, the current state must contain enough information about the history to predict the future.

If the current state contains all the information necessary to determine the future distribution, we do not need to explicitly remember previous states.

10. Markov Chain

A Markov chain is a stochastic process consisting of states and transitions between those states.

The transition probabilities can be represented using a graph. Each node represents a state, while the edges represent transition probabilities.

A Markov chain is memoryless: the probability of the next state depends only on the current state, not on the sequence of states that came before it.

A Markov chain contains a sequence of states, but unlike an MDP, it does not involve agent actions or rewards.

Markov Chain vs. MDP

Markov Chain MDP
States States
Transition probabilities Transition probabilities
No actions Actions
No rewards Rewards
Passive stochastic process Decision-making process

11. Markov Chain Example: Weather

Consider three possible weather states:

  • Sunny
  • Rainy
  • Cloudy

The transition probabilities are:

Current State Sunny Rainy Cloudy
Sunny 0.6 0.2 0.2
Rainy 0.0 0.5 0.5
Cloudy 0.5 0.2 0.3

For example, if today is Sunny, the probability of tomorrow being Sunny is 0.6, Rainy is 0.2, and Cloudy is 0.2.

Python Implementation

import random

# --- Define states ---
states = ["Sunny", "Rainy", "Cloudy"]

# --- Transition probabilities ---
transitions = {
    "Sunny":  [0.6, 0.2, 0.2],
    "Rainy":  [0.0, 0.5, 0.5],
    "Cloudy": [0.5, 0.2, 0.3]
}


# --- Function to get next state ---
def next_state(current_state):

    if current_state not in transitions:
        raise ValueError(f"Invalid state: {current_state}")

    probs = transitions[current_state]

    state = random.choices(
        states,
        probs,
        k=1
    )

    return state[0]


# --- Main simulation ---
def run_simulation(start_state, steps=10):

    state = start_state
    sequence = [state]

    for _ in range(steps):

        next_state_value = next_state(state)

        sequence.append(next_state_value)

        state = next_state_value

    return sequence


# --- Run ---
if __name__ == "__main__":

    result = run_simulation(
        "Cloudy",
        steps=10
    )

    print("Weather sequence:", result)

12. What Breaks the Markov Property?

A process violates the Markov property if knowing the current state is not sufficient to predict the future.

Example 1: Dependence on Older States

Suppose tomorrow's weather depends not only on today's weather but also on the weather from two days ago.

For example:

If it rained two days ago → tomorrow will always be Sunny.

If the current state only contains today's weather, then it does not contain enough information to determine the future. The process is therefore not Markov with respect to that state representation.

Example 2: Stock Market

Suppose the next market state depends on the previous three days:

St+1 depends on St, St-1, St-2

If the state is defined only as the current day's market condition, then the Markov property is violated.

However, we could redefine the state to include the necessary history:

State = (St, St-1, St-2)

With this expanded state representation, the process may satisfy the Markov property.

13. Key Idea

The Markov property is not necessarily about whether the real world has memory. It is about whether the chosen representation of the current state contains enough information to predict the future.

Therefore, if the future depends on information from the past that is missing from the current state, the state representation is not Markov.

In reinforcement learning, designing an appropriate state representation is therefore fundamental to building a valid MDP.
