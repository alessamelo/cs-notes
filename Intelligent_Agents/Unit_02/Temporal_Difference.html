1. Temporal Difference Learning

1.1. Introduction

Temporal Difference (TD) Learning is another family of model-free Reinforcement Learning algorithms. It combines ideas from Dynamic Programming and Monte Carlo methods. Like Monte Carlo methods:
  • It learns directly from interactions with the environment.
  • It does not require a transition probability matrix.
  • It can learn from sampled experience.
Like Dynamic Programming:
  • It uses the Bellman equation as the basis for its updates.
  • It uses bootstrapping to update estimates based on other value estimates.

1.2. What is bootstrapping?

Bootstrapping refers to updating a value estimate using another estimated value rather than waiting until the final return is known. Monte Carlo methods generally wait until an episode finishes before calculating the complete return. Temporal Difference Learning does not need to wait for the episode to terminate. Instead, it uses the immediate reward and the estimated value of the next state. This makes TD learning useful for both episodic and continuing tasks.

1.3. One-step look-ahead

TD methods use a one-step look-ahead approach. Instead of considering the entire episode, the agent uses the most recent transition: $$S_t,A_t,R_{t+1},S_{t+1}$$ The agent updates its value estimate using the observed reward and the value estimate of the next state.

1.4. TD update equation

The general incremental update rule is: $$\text{New Estimate}=\text{Old Estimate}+ \alpha(\text{TD Target}-\text{Old Estimate})$$ For state-value learning: $$V(S_t)\leftarrow V(S_t)+\alpha[ R_{t+1}+\gamma V(S_{t+1})-V(S_t)]$$ Where:
  • $\alpha$: Learning rate.
  • $R_{t+1}$: Immediate reward.
  • $\gamma$: Discount factor.
  • $V(S_{t+1})$: Estimated value of the next state.
The TD error is: $$\delta_t=R_{t+1}+\gamma V(S_{t+1})-V(S_t)$$ It measures the difference between the current estimate and the new target.

1.6. Episodic and continuing tasks

Reinforcement Learning problems can be divided into two categories. Episodic tasks: Each episode has a terminal state. Once the agent reaches that state, the episode ends. Examples include:
  • Solving a maze.
  • Playing a game with a defined ending.
  • Reaching a goal in a grid world.
Continuing tasks: The interaction between the agent and the environment continues indefinitely, without a predefined terminal state. Examples include:
  • Controlling a robot that operates continuously.
  • Managing an industrial process.
  • Continuous resource allocation.
The objective is to maximize cumulative discounted rewards or, in some formulations, the average reward over time.

5. On-Policy and Off-Policy Learning

5.1. Behavior policy and target policy

In Reinforcement Learning, it is important to distinguish between two policies:
  • Behavior policy ($\mu$): The policy that the agent follows when interacting with the environment to generate experience.
  • Target policy ($\pi$): The policy that the agent is trying to evaluate or learn.
Every agent can be understood as having two roles: Behavior policy: It chooses the actions that actually happen and generates the experience data. Think of it as the driver behind the wheel. Target policy: It represents the strategy that the agent wants to learn or improve using the collected data.

5.2. On-Policy Learning

In On-Policy learning, the behavior policy and target policy are the same. $$\mu=\pi$$ The agent learns about the policy it is currently using to interact with the environment. The process is:
  1. The current policy interacts with the environment.
  2. The agent generates new experience.
  3. The agent updates its policy using that experience.
  4. The updated policy interacts with the environment again.
  5. The process repeats.
The agent learns from its own current behavior. Examples of On-Policy algorithms include:
  • SARSA.
  • REINFORCE.
  • A2C and A3C.
  • TRPO.
  • PPO.

5.3. Off-Policy Learning

In Off-Policy learning, the behavior policy and target policy are different. $$\mu\neq\pi$$ The agent can learn a target policy using experience generated by another behavior policy. This experience can come from:
  • Previous versions of the agent.
  • Random exploration.
  • Other agents.
  • Human demonstrations.
  • Previously collected experiences.
Experience can be stored in a replay buffer and sampled multiple times for learning. This allows the agent to reuse previously collected data instead of requiring every update to come from newly generated experience. Q-Learning is a fundamental example of an Off-Policy algorithm.

5.4. On-Policy vs. Off-Policy: Real-world examples

Example 1: Learning to ride a bicycle On-Policy: You ride the bicycle yourself, wobble, lose balance, fall, and adjust your technique. Every lesson comes from your own current behavior. Off-Policy: You watch videos of other people riding bicycles, including beginners making mistakes, and learn what good riding looks like from their experiences. Example 2: Improving at chess On-Policy: You study only your recent games, generated using your current playing strategy. Off-Policy: You study grandmaster games and beginner mistakes to learn better strategies using experience generated by other players.

5.5. Main differences

Characteristic On-Policy Off-Policy
Behavior policy Same as target policy Different from target policy
Experience source Current policy Can come from other policies
Experience reuse Usually limited in standard implementations Can reuse previously collected data
Example SARSA Q-Learning

Important: On-Policy does not mean that the agent cannot use exploration. It can use an exploratory policy, such as epsilon-greedy. The distinction is that the target policy is the same policy used to generate experience.

6. SARSA Algorithm

6.1. Introduction

SARSA is a model-free, On-Policy Temporal Difference control algorithm. It learns the action-value function $Q^\pi(s,a)$ by interacting with the environment and updating its estimates after each transition. The name SARSA comes from the five elements used in its update:
  1. S: Current state ($S_t$).
  2. A: Current action ($A_t$).
  3. R: Reward received ($R_{t+1}$).
  4. S: Next state ($S_{t+1}$).
  5. A: Next action ($A_{t+1}$).
Therefore, the experience required for SARSA is: $$S_t,A_t,R_{t+1},S_{t+1},A_{t+1}$$

6.2. SARSA update equation

The SARSA update rule is: $$Q(S_t,A_t)\leftarrow Q(S_t,A_t)+\alpha[ R_{t+1}+\gamma Q(S_{t+1},A_{t+1})-Q(S_t,A_t)]$$ Where:
  • $Q(S_t,A_t)$: Current estimated value of the state-action pair.
  • $\alpha$: Learning rate.
  • $R_{t+1}$: Reward received after performing the action.
  • $\gamma$: Discount factor.
  • $Q(S_{t+1},A_{t+1})$: Estimated value of the next state-action pair.
The key characteristic is that SARSA uses the actual next action selected by the behavior policy.

6.3. Why is SARSA On-Policy?

SARSA is On-Policy because the action used in the update is the action actually selected by the current policy. The agent learns from the same behavior it uses to interact with the environment. For example, if the agent uses an epsilon-greedy policy, the next action may be exploratory rather than greedy. SARSA incorporates that actual exploratory action into its update.

6.4. Exploration and exploitation

SARSA uses an exploration rate, commonly represented by $\epsilon$. Exploration: The agent searches for new actions to discover more information about the environment. Exploitation: The agent takes advantage of its current knowledge by selecting actions with high estimated values.

6.5. Epsilon-Greedy policy

SARSA commonly uses an epsilon-greedy policy. The policy selects:
  • The action with the highest estimated Q-value with probability $1-\epsilon$.
  • A random action with probability $\epsilon$.
Mathematically, a simple version is: $$\pi(a|s)= \begin{cases} 1-\epsilon+\frac{\epsilon}{|A|}, & a=\arg\max_a Q(s,a)\\ \frac{\epsilon}{|A|}, & \text{otherwise} \end{cases}$$ This assumes uniform random exploration over the available actions and a unique greedy action.

6.6. SARSA algorithm steps

  1. Initialize the Q-table with arbitrary values, usually zeros.
  2. Initialize the agent in a starting state.
  3. Select an action using the epsilon-greedy policy.
  4. Execute the action and observe the reward and next state.
  5. Select the next action using the same epsilon-greedy policy.
  6. Update the Q-value using the SARSA equation.
  7. Move to the next state and continue.
  8. Repeat until the episode reaches a terminal state.
  9. Start another episode and continue learning.

For a terminal next state, the next-state Q-value is treated as zero, and the update target is simply the terminal reward.

6.7. SARSA and episodic tasks

SARSA can be used in episodic tasks, where each episode has a terminal state. For example, in a grid world:
  • The agent starts at an initial position.
  • It explores the environment.
  • It receives rewards and penalties.
  • The episode ends when it reaches the goal or a terminal trap.
SARSA can also be extended to continuing tasks.

6.8. SARSA and risk

Because SARSA learns from the actions actually selected by its exploratory policy, it accounts for the consequences of exploration. For example, if an exploratory action can lead the agent toward a trap, this possibility influences the learned Q-values. This can make SARSA learn a more conservative strategy than Q-Learning in environments where exploration itself can be dangerous.

7. Q-Learning Algorithm

7.1. Introduction

Q-Learning is a model-free, Off-Policy Temporal Difference control algorithm. It learns the optimal action-value function: $$Q^*(s,a)$$ Unlike SARSA, Q-Learning does not use the next action actually selected by the behavior policy in its update. Instead, it assumes that the agent will choose the best possible action in the next state.

7.2. Bellman optimality equation for Q-values

Recall the Bellman optimality equation for the optimal action-value function: $$Q^*(s,a)=\mathbb{E}[R_{t+1}+ \gamma\max_{a'}Q^*(S_{t+1},a')]$$ This equation states that the optimal Q-value of a state-action pair is the expected immediate reward plus the discounted maximum Q-value of the next state.

7.3. Q-Learning update equation

The Q-Learning update rule is: $$Q(S_t,A_t)\leftarrow Q(S_t,A_t)+\alpha[ R_{t+1}+\gamma\max_{a'}Q(S_{t+1},a')-Q(S_t,A_t)]$$ Where:
  • $Q(S_t,A_t)$: Current estimate.
  • $\alpha$: Learning rate.
  • $R_{t+1}$: Immediate reward.
  • $\gamma$: Discount factor.
  • $\max_{a'}Q(S_{t+1},a')$: Maximum estimated value among the available next actions.

7.4. Why is Q-Learning Off-Policy?

Q-Learning is Off-Policy because it learns the optimal greedy policy while allowing the behavior policy to explore the environment. The behavior policy might use epsilon-greedy exploration. However, the update always uses the maximum estimated Q-value in the next state. Therefore:
  • The behavior policy determines which action is actually performed.
  • The target policy is greedy with respect to the Q-values.

7.5. Q-Learning algorithm steps

  1. Initialize the Q-table.
  2. Initialize the agent in a starting state.
  3. Select an action using the behavior policy, commonly epsilon-greedy.
  4. Execute the action.
  5. Observe the reward and next state.
  6. Find the maximum Q-value among the available actions in the next state.
  7. Update the current Q-value using the Q-Learning equation.
  8. Continue until the episode terminates.
  9. Repeat the process for multiple episodes.

For terminal states, the future Q-value is zero because no additional actions can be taken.

7.6. SARSA vs. Q-Learning

7.7. Understanding the difference with an example

Imagine that an agent is navigating a grid world and is currently in state $S_t$. It selects an action and reaches state $S_{t+1}$. Suppose the next state's Q-values are:
  • Up: 10
  • Down: 8
  • Left: 5
  • Right: 2
Suppose the epsilon-greedy policy selects the action "Down" because of exploration. SARSA uses: $$Q(S_{t+1},Down)=8$$ Q-Learning uses: $$\max_{a'}Q(S_{t+1},a')=10$$ Therefore, SARSA updates its estimate using the actual next action, while Q-Learning uses the maximum estimated action value. This is the fundamental difference between these two algorithms.
