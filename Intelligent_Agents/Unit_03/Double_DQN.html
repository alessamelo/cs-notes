1. Introduction to DQN

1.1. From Q-Learning to Deep Q-Networks

Traditional Q-Learning uses a Q-table to store the estimated value of every state-action pair. However, when the state space becomes very large, storing all possible Q-values becomes impractical. Deep Q-Networks (DQN) address this limitation by using a neural network to approximate the action-value function. Instead of maintaining a table, the agent uses a neural network to estimate the Q-values associated with the available actions. The network learns the mapping: $$Q(s,a;\theta)$$ Where:
  • $s$: Current state.
  • $a$: Selected action.
  • $\theta$: Parameters (weights and biases) of the neural network.
  • $Q(s,a;\theta)$: Estimated value of taking action $a$ in state $s$.
The objective is to approximate the optimal action-value function: $$Q^*(s,a)$$

1.2. The problem with standard Q-Learning in deep networks

In traditional Q-Learning, the Q-table is updated directly using the Bellman equation. In DQN, the Q-values are approximated using a neural network. Therefore, the network parameters must be adjusted through optimization. The learning process introduces additional challenges:
  • Consecutive experiences are highly correlated.
  • The target values change while the network is being trained.
  • Small estimation errors can influence future predictions.
  • The network can become unstable during training.
DQN introduces two fundamental mechanisms to improve training stability:
  1. Experience Replay: Stores and samples previous experiences.
  2. Target Network: Uses a separate network to calculate more stable target values.

2. Experience Replay

2.1. What is Experience Replay?

Experience Replay is a mechanism that stores the agent's previous interactions with the environment in a data structure called the Replay Buffer. Instead of training the neural network using only the most recent experience, the agent stores transitions and randomly samples a mini-batch for training. Each transition contains: $$ (S_t,A_t,R_{t+1},S_{t+1},Done) $$ Where:
  • $S_t$: Current state.
  • $A_t$: Action performed.
  • $R_{t+1}$: Reward received.
  • $S_{t+1}$: Next state.
  • $Done$: Indicates whether the episode terminated.

2.2. Replay Buffer and Mini-batches

The Replay Buffer stores a collection of transitions. During training, the agent randomly selects a mini-batch of experiences from the buffer. For example: 
Replay Buffer:
[
    (state_1, action_1, reward_1, next_state_1, done_1),
    (state_2, action_2, reward_2, next_state_2, done_2),
    (state_3, action_3, reward_3, next_state_3, done_3),
    ...
]
A mini-batch is a subset of these stored transitions. For example, if the batch size is 64, the network trains using 64 randomly sampled transitions. Important: The mini-batch is not the Replay Buffer itself. It is a sample taken from the Replay Buffer.

2.3. Why do we use Experience Replay?

Experience Replay provides several advantages:
  • Reduces correlation: Consecutive transitions are often highly correlated. Random sampling makes the training batches less dependent on their original temporal order.
  • Improves data efficiency: The same experience can be used multiple times during training.
  • Stabilizes learning: It helps reduce abrupt changes caused by learning exclusively from recent transitions.
  • Improves training efficiency: Mini-batches allow the network to perform vectorized computations.

3. Target Network

3.1. What is a Target Network?

A Target Network is a second neural network used by DQN to calculate the target Q-values during training. A standard DQN architecture maintains two networks:
  1. Online Network: The network that is actively trained and updated through gradient descent.
  2. Target Network: A separate, temporarily frozen copy of the online network used to calculate target values.
Both networks have the same architecture, but they do not necessarily have the same parameters at every training step. We represent their parameters as:
  • Online Network: $\theta$
  • Target Network: $\theta^-$

3.2. Why do we need a Target Network?

In standard Q-Learning, the update target is: $$y_t=R_{t+1}+\gamma\max_{a'}Q(S_{t+1},a')$$ If we use the same neural network to calculate both the current Q-value and the target Q-value, the network is constantly changing the values used as its own learning targets. This creates a moving-target problem. Every time the online network is updated:
  • Its current predictions change.
  • The estimated next-state Q-values also change.
  • The target used to calculate the loss changes.
This can make the learning process unstable. The Target Network addresses this problem by providing a separate set of parameters for calculating the targets.

3.3. Frozen copy of the Online Network

Initially, the Target Network receives a copy of the Online Network's parameters. $$\theta^- \leftarrow \theta$$ This means both networks start with the same weights and biases. However, during normal training:
  • The Online Network is continuously updated.
  • The Target Network remains frozen between synchronization steps.
After a predefined number of training steps, the current Online Network parameters are copied into the Target Network. $$\theta^- \leftarrow \theta$$ This process is called a hard update or hard synchronization.

3.4. Target Network synchronization

Suppose we define a synchronization interval $C$. Every $C$ training steps, we copy the Online Network's parameters into the Target Network. For example: 
if training_step % C == 0:
    target_network.load_state_dict(
        online_network.state_dict()
    )
The process works as follows:
  1. Initialize the Online Network.
  2. Copy its parameters into the Target Network.
  3. Train the Online Network using mini-batches from the Replay Buffer.
  4. Keep the Target Network frozen while the Online Network changes.
  5. After every $C$ training steps, synchronize the Target Network.
  6. Repeat the process.

3.5. Online Network vs. Target Network behavior

The two networks have different update behaviors. Online Network: Its parameters change dynamically during training because gradient descent continuously adjusts its weights. Target Network: Its parameters remain constant between synchronization steps and change only when a copy of the Online Network is performed. Therefore, if we visualize the parameters over time:
  • The Online Network follows a continuously changing trajectory.
  • The Target Network follows a staircase-like trajectory.

The staircase behavior occurs because the target parameters remain fixed for several steps and then suddenly change when the networks are synchronized.

3.6. Alternative: Soft Updates

Besides hard synchronization, a Target Network can also be updated gradually using soft updates. Instead of copying all parameters at once, the Target Network slowly moves toward the Online Network. $$\theta^- \leftarrow \tau\theta+(1-\tau)\theta^-$$ Where:
  • $\theta$: Online Network parameters.
  • $\theta^-$: Target Network parameters.
  • $\tau$: Small update coefficient, usually much smaller than 1.
A small value of $\tau$ means the Target Network changes gradually. This avoids the sudden parameter changes associated with hard synchronization.

4. DQN Training Process

4.1. Calculating the Target Q-value

In standard DQN, the Target Network calculates the maximum Q-value associated with the next state. The target is: $$y_t=R_{t+1}+\gamma(1-Done) \max_{a'}Q(S_{t+1},a';\theta^-)$$ Where:
  • $R_{t+1}$: Immediate reward.
  • $\gamma$: Discount factor.
  • $Done$: Terminal-state indicator.
  • $S_{t+1}$: Next state.
  • $\theta^-$: Target Network parameters.
The term $(1-Done)$ ensures that no future reward is included when the transition reaches a terminal state. If the transition is terminal: $$y_t=R_{t+1}$$ Otherwise: $$y_t=R_{t+1}+\gamma\max_{a'}Q(S_{t+1},a';\theta^-)$$

4.2. Calculating the Online Q-value

The Online Network calculates the predicted Q-value corresponding to the action actually performed. $$Q(S_t,A_t;\theta)$$ The network receives the current state and produces Q-values for the available actions. We select the prediction corresponding to the action stored in the sampled transition.

4.3. Loss Function

Once we have the predicted Q-value from the Online Network and the target Q-value from the Target Network, we calculate the loss. A common choice is the Mean Squared Error (MSE): $$L(\theta)= \mathbb{E}\left[ \left(y_t-Q(S_t,A_t;\theta)\right)^2 \right]$$ For a mini-batch of size $N$: $$L(\theta)=\frac{1}{N}\sum_{i=1}^{N} \left(y_i-Q(S_i,A_i;\theta)\right)^2$$ The loss measures the difference between the predicted Q-values and their target values.

4.4. Updating the Online Network

After calculating the loss, we use backpropagation and an optimizer to update the Online Network parameters. The general gradient descent update is: $$\theta \leftarrow \theta-\alpha\nabla_\theta L(\theta)$$ Where:
  • $\theta$: Online Network parameters.
  • $\alpha$: Learning rate.
  • $\nabla_\theta L(\theta)$: Gradient of the loss with respect to the Online Network parameters.
The Target Network does not receive this gradient update. It remains frozen until the next synchronization step.

4.5. Complete DQN training cycle

The complete process is:
  1. Initialize the Online Network with parameters $\theta$.
  2. Initialize the Target Network with parameters $\theta^-=\theta$.
  3. Initialize the Replay Buffer.
  4. Observe the current state.
  5. Select an action using an exploration strategy, such as epsilon-greedy.
  6. Execute the action and observe the reward and next state.
  7. Store the transition in the Replay Buffer.
  8. Sample a mini-batch of transitions from the Replay Buffer.
  9. Use the Online Network to calculate the predicted Q-values.
  10. Use the Target Network to calculate the target Q-values.
  11. Calculate the loss between the predicted values and the targets.
  12. Update the Online Network through backpropagation and gradient descent.
  13. After every $C$ training steps, copy the Online Network parameters into the Target Network.
  14. Repeat the process.

4.6. Why does this stabilize learning?

The main advantage of the Target Network is that it prevents the target values from changing after every Online Network update. The Online Network can improve its predictions without immediately changing the network responsible for generating the targets. This reduces the moving-target problem and helps stabilize the learning process.

Important: The Target Network does not eliminate all instability. It makes the learning targets more stable between synchronization steps, but DQN can still experience divergence or oscillations depending on the environment, learning rate, replay buffer, and other hyperparameters.

5. Problems with Standard DQN: Overestimation Bias

5.1. What is Overestimation Bias?

Standard DQN can suffer from overestimation bias. The problem occurs because the algorithm uses the maximum estimated Q-value to calculate its target. $$y_t=R_{t+1}+\gamma\max_{a'}Q(S_{t+1},a';\theta^-)$$ However, neural networks do not produce perfectly accurate Q-value estimates. Their predictions can contain estimation errors or noise. When we take the maximum among several noisy estimates, the selected value tends to be positively biased. In other words, the algorithm may systematically overestimate the value of the best available action.

5.2. Why does overestimation happen?

Consider a state with three possible actions. Suppose the true Q-values are:
Action True Q-value Estimated Q-value
Up 10 12
Down 9 8
Left 7 6
The network estimates that the action "Up" has a value of 12, even though its true value is 10. Standard DQN uses: $$\max(12,8,6)=12$$ Therefore, the algorithm uses an overestimated value in its target. This problem is related to the maximization operation. When estimates contain noise, selecting the maximum tends to select values with positive estimation errors.

5.3. Why is this a problem?

Overestimation can negatively affect learning because:
  • The agent may believe that some actions are better than they actually are.
  • The estimated Q-values can become excessively optimistic.
  • The agent may prefer actions based on inaccurate estimates.
  • Overestimated targets can propagate through subsequent updates.
  • Training performance and stability can deteriorate.
Therefore, we need a method that reduces the influence of overestimated Q-values.

6. Double DQN

6.1. Introduction

Double DQN is an extension of standard DQN designed to reduce overestimation bias. It separates two operations that standard DQN performs using the same target network:
  1. Selecting the best next action.
  2. Evaluating the value of that selected action.
In Double DQN, these operations are performed using different networks.
  • Online Network: Selects the next action.
  • Target Network: Evaluates the selected action.
This separation helps reduce the positive bias caused by maximizing noisy value estimates.

6.2. The main idea: Selection vs. Evaluation

Consider two networks:
  • $Q_1$: Online Network.
  • $Q_2$: Target Network.
The Online Network selects the action with the highest estimated Q-value. $$a^*=\arg\max_{a'}Q(S_{t+1},a';\theta)$$ The Target Network then evaluates the selected action. $$Q(S_{t+1},a^*;\theta^-)$$ Therefore:
  • $Q_1$ determines which action is considered the best.
  • $Q_2$ estimates how good that action actually is.
This is the fundamental difference between DQN and Double DQN.

6.3. Double DQN target equation

The Double DQN target is: $$y_t=R_{t+1}+\gamma(1-Done) Q\left(S_{t+1}, \arg\max_{a'}Q(S_{t+1},a';\theta); \theta^-\right)$$ Where:
  • $\theta$: Online Network parameters.
  • $\theta^-$: Target Network parameters.
  • $\arg\max_{a'}Q(S_{t+1},a';\theta)$: Action selected by the Online Network.
  • $Q(S_{t+1},a^*;\theta^-)$: Evaluation of that action by the Target Network.
For terminal transitions: $$y_t=R_{t+1}$$ The Online Network still calculates the predicted Q-value for the current state-action pair: $$Q(S_t,A_t;\theta)$$ We then calculate the loss: $$L(\theta)= \mathbb{E}\left[ (y_t-Q(S_t,A_t;\theta))^2 \right]$$ The Online Network is updated through gradient descent, while the target calculation is treated as a constant during that update.

6.4. Step-by-step example

Consider the following next-state action values predicted by the Online Network:
Action Online Network ($Q_1$) Target Network ($Q_2$)
Up 12 9
Down 8 10
Left 6 7
Step 1: Online Network selects the best action. The Online Network predicts: $$Q_1(Up)=12$$ $$Q_1(Down)=8$$ $$Q_1(Left)=6$$ Therefore: $$a^*=Up$$ Step 2: Target Network evaluates the selected action. The Target Network evaluates the action "Up": $$Q_2(Up)=9$$ Step 3: Calculate the target. Assuming a reward of 1 and a discount factor of 0.99, with a non-terminal transition: $$y=1+0.99(9)$$ $$y=9.91$$ Double DQN uses 9 as the estimated value of the selected action rather than using the maximum value predicted by the Target Network. This illustrates how the two networks perform different operations.

6.5. How does Double DQN reduce overestimation?

Standard DQN uses the Target Network to select and evaluate the maximum action value. Double DQN separates these operations. By using the Online Network to select the action and the Target Network to evaluate it, the algorithm reduces the direct coupling between action selection and value estimation. This generally reduces the overestimation bias. However, Double DQN does not eliminate all estimation errors or guarantee that Q-values will never be overestimated.

7. Standard DQN vs. Double DQN

7.1. Main differences

Characteristic Standard DQN Double DQN
Online Network Predicts current Q-values. Predicts current Q-values and selects the next action.
Target Network Selects and evaluates the maximum next-state Q-value. Evaluates the action selected by the Online Network.
Target calculation Maximum Q-value from Target Network. Online selection + Target evaluation.
Overestimation bias More susceptible. Generally reduced.
Experience Replay Yes Yes
Target Network Yes Yes
Loss function Usually MSE or Huber loss. Usually MSE or Huber loss.

7.2. Mathematical comparison

Standard DQN: $$y_t^{DQN}=R_{t+1}+\gamma(1-Done) \max_{a'}Q(S_{t+1},a';\theta^-)$$ The Target Network selects and evaluates the next action. Double DQN: $$y_t^{DoubleDQN}=R_{t+1}+\gamma(1-Done) Q(S_{t+1}, \arg\max_{a'}Q(S_{t+1},a';\theta); \theta^-)$$ The Online Network selects the action, and the Target Network evaluates it.

7.3. Shared components

Both algorithms use:
  • An Online Network.
  • A Target Network.
  • A Replay Buffer.
  • Mini-batch sampling.
  • Backpropagation.
  • Gradient descent.
  • An exploration strategy, commonly epsilon-greedy.
  • A target synchronization mechanism.
The primary difference is how the next-state target is calculated.

8. Implementation Considerations

8.1. Standard DQN pseudocode

Initialize online_network with parameters theta
Initialize target_network with parameters theta_minus = theta
Initialize replay_buffer

for each episode:

    state = environment.reset()

    while not done:

        action = epsilon_greedy(online_network, state)

        next_state, reward, done = environment.step(action)

        replay_buffer.add(
            state, action, reward, next_state, done
        )

        if replay_buffer.size() >= batch_size:

            batch = replay_buffer.sample(batch_size)

            current_q = online_network(
                batch.states
            ).gather(batch.actions)

            with no_grad:
                next_q = target_network(
                    batch.next_states
                ).max(dim=1).values

                target_q = batch.rewards + gamma * (
                    1 - batch.dones
                ) * next_q

            loss = loss_function(current_q, target_q)

            optimizer.zero_grad()
            loss.backward()
            optimizer.step()

        if training_step % C == 0:
            target_network.load_state_dict(
                online_network.state_dict()
            )

        state = next_state

8.2. Double DQN pseudocode

Initialize online_network with parameters theta
Initialize target_network with parameters theta_minus = theta
Initialize replay_buffer

for each episode:

    state = environment.reset()

    while not done:

        action = epsilon_greedy(online_network, state)

        next_state, reward, done = environment.step(action)

        replay_buffer.add(
            state, action, reward, next_state, done
        )

        if replay_buffer.size() >= batch_size:

            batch = replay_buffer.sample(batch_size)

            current_q = online_network(
                batch.states
            ).gather(batch.actions)

            with no_grad:

                # Online network selects the action
                next_actions = online_network(
                    batch.next_states
                ).argmax(dim=1)

                # Target network evaluates the selected action
                next_q = target_network(
                    batch.next_states
                ).gather(
                    1, next_actions.unsqueeze(1)
                ).squeeze(1)

                target_q = batch.rewards + gamma * (
                    1 - batch.dones
                ) * next_q

            loss = loss_function(current_q, target_q)

            optimizer.zero_grad()
            loss.backward()
            optimizer.step()

        if training_step % C == 0:
            target_network.load_state_dict(
                online_network.state_dict()
            )

        state = next_state

These examples use PyTorch-style pseudocode. The exact implementation may vary depending on the environment and network architecture.

8.3. Important implementation details

  • The Target Network should not receive optimizer updates.
  • Target calculations should be performed without gradient tracking.
  • The Online Network is updated using the loss.
  • Terminal transitions must not include future Q-values.
  • The Replay Buffer should contain enough experiences before training begins.
  • Target synchronization must be performed using the intended training-step interval.
  • The next-state action selection in Double DQN must use the Online Network.
  • The evaluation of that selected action must use the Target Network.

9. Final Summary

9.1. Important concepts

  • DQN: Uses a neural network to approximate the Q-function.
  • Online Network: The network that is continuously trained.
  • Target Network: A frozen copy used to calculate target Q-values.
  • Replay Buffer: Stores previous transitions.
  • Mini-batch: A randomly sampled subset of the Replay Buffer.
  • Hard Update: Copies the Online Network parameters into the Target Network after a predefined number of steps.
  • Soft Update: Gradually updates Target Network parameters.
  • Overestimation Bias: The tendency of maximization over noisy Q-value estimates to produce overly optimistic values.
  • Double DQN: Separates action selection from action evaluation.

9.2. Equations to remember

Target Network initialization: $$\theta^- \leftarrow \theta$$ Hard synchronization: $$\theta^- \leftarrow \theta \quad \text{every } C \text{ training steps}$$ Soft synchronization: $$\theta^- \leftarrow \tau\theta+(1-\tau)\theta^-$$ Standard DQN target: $$y_t=R_{t+1}+\gamma(1-Done) \max_{a'}Q(S_{t+1},a';\theta^-)$$ DQN loss: $$L(\theta)= \mathbb{E}[(y_t-Q(S_t,A_t;\theta))^2]$$ Gradient descent: $$\theta\leftarrow\theta-\alpha\nabla_\theta L(\theta)$$ Double DQN action selection: $$a^*=\arg\max_{a'}Q(S_{t+1},a';\theta)$$ Double DQN target: $$y_t=R_{t+1}+\gamma(1-Done) Q(S_{t+1},a^*;\theta^-)$$

9.3. The most important difference

Standard DQN: The Target Network selects the best next action and evaluates its value. Double DQN: The Online Network selects the best next action, while the Target Network evaluates that action.
This separation reduces the overestimation bias associated with the maximization operation in standard DQN.
