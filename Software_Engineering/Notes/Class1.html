1. What Is Software?

Software is a computer program together with its corresponding documentation.

It is not necessary to document every line of code. However, important parts of the system should be documented so that other developers can understand and maintain the software.

Important elements to document include:

  • Important blocks of code
  • Definitions and purpose of variables
  • Important design decisions
  • Architecture and system behavior

Documentation facilitates:

  • Understanding
  • Maintenance
  • Collaboration
  • Future evolution of the software

2. Software Engineering

Software Engineering studies all aspects involved in the production and evolution of software.

It includes:

  • Software processes
  • Development methods
  • Development tools
  • Project and development management
  • Quality assurance
  • Software maintenance and evolution

Modern economies depend heavily on software. Technology has also changed the business models of many companies.

Example: Netflix and Blockbuster

Netflix emerged as an alternative to the traditional video rental model associated with companies such as Blockbuster.

The broader lesson is that companies and software systems must be capable of adapting to technological and market changes.

3. Software in Modern Infrastructure

A large portion of modern infrastructure is controlled or supported by computer systems.

Smart Grids

Smart electrical grids incorporate communication and computing systems into electrical infrastructure, including smart meters.

Some smart meters and related infrastructure use operating systems based on Linux.

Infrastructure and Public Services

Many public services and infrastructure systems depend on computer-based control systems.

Modern Electronic Products

Most modern electronic products contain some form of embedded software.

Smart Vehicles

Modern vehicles can use sensors and communication systems to monitor their environment, traffic conditions, and vehicle state.

Data Analysis Systems

Large volumes of data can be analyzed to create profiles and support automated decision-making.

4. Software in Everyday Life

Amazon

Companies such as Amazon use software to automate many processes, including logistics, recommendations, and customer interactions.

Alexa

Voice assistants such as Alexa rely on cloud-based services to process requests and store information.

Home Assistant

Home Assistant is an open-source home automation platform.

  • Open-source software
  • Can run on devices such as Raspberry Pi
  • Can operate locally
  • Can be configured to minimize external data sharing

5. Software Documentation

Modern software development often operates under short delivery cycles. As a result, developers may be tempted to reduce the amount of documentation they produce.

However, documentation remains important because software is rarely static.

Good documentation supports:

  • Maintenance — understanding existing code when making changes.
  • Scalability — understanding how the system is structured.
  • Teamwork — allowing multiple developers to understand the system.
  • Evolution — making future modifications easier.

6. Software Development Process

Software engineering defines processes and activities that help produce software systematically and with appropriate quality.

1. Requirements

Requirements describe what the system needs to provide.

Type Meaning
Functional requirements Describe what the system must do.
Non-functional requirements Describe constraints and quality attributes such as performance, security, availability, and usability.

2. Design

The design is based on the requirements and determines how the system will be structured and implemented.

UML (Unified Modeling Language) can be used to represent software systems using standardized diagrams and notation.

3. Implementation

The software is developed by writing and integrating the source code.

4. Validation and Testing

The system is tested to determine whether it satisfies its requirements and to identify errors or failures.

5. Evolution

Software must often be modified after deployment to respond to changing requirements, technologies, environments, or user needs.

Software development does not end when the first version is released. Software must evolve throughout its useful lifetime.

7. Software Projects

A software development activity can be considered a project when it has clearly defined characteristics.

  • Product: something that will be produced.
  • Scope: a defined set of objectives and work.
  • Time frame: a defined temporal period.

8. Product Life Cycle

Products commonly pass through several stages during their lifetime.

Introduction → Growth → Maturity → Decline

Introduction

The product is conceived, developed, and introduced to the market.

Growth

Adoption and demand increase.

Maturity

The product reaches a relatively stable stage of market adoption.

Decline

Demand decreases as technology, competitors, or customer preferences change.

Adaptation to technological and market changes can delay or prevent decline.

9. Types of Software Products

Generic Products

Generic software products are developed by a company for a broad market rather than for one specific customer.

  • Developed by a software company
  • Sold to the general public
  • Usually operate as stand-alone products or services
  • Examples include many mobile applications

In this case, the software developer or company generally controls the product requirements.

Customized Products

Customized software is developed for a specific client or organization.

  • Developed for a specific customer
  • Requirements are defined according to the customer's needs
  • The customer has significant influence over requested changes
Main difference: who controls the requirements.

Generic product → the software company controls the requirements.
Customized product → the client has primary control over the requirements.

10. Open-Source Software Licenses

When using open-source software, it is important to examine the license associated with the code.

Open-source does not mean that all software has identical usage conditions.

Depending on the license, different obligations may apply.

  • Some licenses require derivative software to also be released under open-source conditions.
  • Other licenses allow the code to be incorporated into proprietary software.
  • Some licenses require attribution to the original author.
Always review the license before incorporating open-source code into a project.

11. Software Quality Attributes

Software engineering is not only concerned with whether a program works. It also considers important quality attributes that determine how well the software behaves and how easy it is to maintain.

12. Maintainability

Maintainability means that software should be written in a way that makes modifications and changes as easy as possible.

Software cannot realistically be expected to remain unchanged for its entire useful lifetime.

Requirements, technologies, security threats, hardware, and user expectations change over time.

Therefore, software should be designed so that developers can efficiently:

  • Fix bugs
  • Add features
  • Modify existing behavior
  • Adapt to new technologies
  • Improve performance

13. Dependability and Security

Dependability refers to the degree to which users can trust a software system to provide its expected service.

Availability

The system should be available when it is needed.

Availability: Is the system accessible and operational when required?

Reliability

The system should perform its required functions correctly and consistently.

Reliability: Does the system produce correct results and behave consistently?

Security and Safety

The system should protect its data and functionality from malicious users and prevent dangerous failures where applicable.

  • Prevent unauthorized access
  • Protect data
  • Prevent malicious modification
  • Reduce the consequences of failures

14. TCP and UDP — Reliability Example

TCP and UDP are transport-layer protocols used to transmit data over networks, but they provide different guarantees.

TCP UDP
Provides reliable, ordered delivery. Does not guarantee reliable or ordered delivery.
Can retransmit lost data. Does not perform TCP-style retransmission automatically.
More overhead. Lower overhead and often lower latency.

The choice between them depends on the requirements of the application.

15. Efficiency

Efficient software should avoid wasteful use of system resources.

Efficiency can involve several resources, including:

  • Execution time
  • CPU usage
  • RAM usage
  • Storage
  • Network bandwidth
  • Energy consumption

Example: AI Models

For an AI system, efficiency could be measured using metrics such as:

  • Prediction or inference time
  • Memory consumption
  • CPU/GPU utilization
  • Energy consumption

16. Acceptability

Software must be acceptable to the type of users for whom it was designed.

Acceptability includes more than simply making the software functional. The system should fit the users' needs, expectations, environment, and capabilities.

Factors can include:

  • Usability
  • Interface design
  • Compatibility with existing systems
  • Performance
  • Cost
  • User expectations

17. Example: ATMs

Automated Teller Machines (ATMs) are a useful example of software that may remain in use for many years.

A major reason why such systems are not modernized as frequently as consumer applications is the cost and complexity of modernization.

Updating the system may require changes to:

  • Software
  • Hardware
  • Security infrastructure
  • Banking systems
  • Testing and certification
  • Physical equipment
This illustrates why maintainability and software evolution are essential: software often has to coexist with hardware and other systems for many years.

18. Summary of Software Quality Attributes

Attribute Question
Maintainability How easily can the software be modified and evolved?
Availability Is the system available when users need it?
Reliability Does the system consistently produce correct results?
Security Is the system protected against unauthorized or malicious access?
Safety Does the system avoid causing unacceptable harm when failures occur?
Efficiency Does the system use computational resources efficiently?
Acceptability Is the system appropriate and usable for its intended users?

19. Main Ideas to Remember

  • Software includes both the program and its relevant documentation.
  • Software engineering covers the processes, methods, tools, management, and quality aspects involved in software production.
  • Software must be designed with its future evolution in mind.
  • Requirements define what the system should provide, while non-functional requirements describe constraints and quality characteristics.
  • Software development involves requirements, design, implementation, validation/testing, and evolution.
  • Generic and customized products differ mainly in who controls the requirements.
  • Open-source software still has licensing requirements.
  • Good software is not simply functional; it should also be maintainable, dependable, secure, efficient, and acceptable to its users.
