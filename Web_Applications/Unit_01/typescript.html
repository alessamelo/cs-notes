1. What is TypeScript?

TypeScript is a programming language developed by Microsoft and built as a superset of JavaScript.

It extends JavaScript by adding features such as static typing, interfaces, type annotations, generics, and other features that help developers write and maintain larger programs.

Important: TypeScript is not executed directly by browsers. TypeScript code is normally compiled/transpiled into JavaScript, which can then be executed by a browser or a JavaScript runtime such as Node.js.
Basic process:

TypeScript → JavaScript → Browser / Node.js

2. Static Typing

One of the main features TypeScript adds to JavaScript is static typing.

Static types allow us to specify what kind of value a variable, parameter, or function should contain or return.

The main goal is to detect many errors before the program is executed.

JavaScript

let age = 20;

age = "twenty";

JavaScript allows this because variables are dynamically typed. The same variable can contain values of different types during execution.

TypeScript

let age: number = 20;

age = "twenty";

TypeScript reports an error because age was declared as a number.

3. JavaScript vs TypeScript: Dynamic and Static Typing

JavaScript TypeScript
Dynamically typed. Statically typed.
Types are determined and checked during execution. Types can be checked before execution.
Variables can generally change the type of value they contain. A variable can be restricted to a specific type.
Many type-related errors appear at runtime. Many type-related errors can be detected during development or compilation.
Does not require a separate TypeScript compilation step. Usually compiled/transpiled into JavaScript before execution.

4. Relationship with JavaScript

TypeScript is designed to be highly compatible with JavaScript.

In general, valid JavaScript code can also be used as TypeScript code.

TypeScript adds additional syntax and type information on top of JavaScript.

5. Functions — Syntax Differences

JavaScript

function add(a, b) {
    return a + b;
}

JavaScript does not require us to explicitly declare the types of the parameters or return value.

TypeScript

function add(a: number, b: number): number {
    return a + b;
}

TypeScript allows us to specify:

  • a: number — parameter a must be a number.
  • b: number — parameter b must be a number.
  • : number — the function must return a number.

6. Variables — Syntax Differences

JavaScript

let name = "Alex";
let age = 20;
let student = true;

TypeScript

let name: string = "Alex";
let age: number = 20;
let student: boolean = true;

Type annotations are written after the variable name using a colon. 

variableName: type

TypeScript can also infer types automatically. 

let age = 20;
// TypeScript infers: number

7. Basic TypeScript Types

let username: string = "Alice";

let age: number = 21;

let isStudent: boolean = true;

let nothing: null = null;

let value: undefined = undefined;

8. Arrays

JavaScript

let numbers = [1, 2, 3, 4];

let names = ["Alice", "Bob", "Charlie"];

TypeScript

let numbers: number[] = [1, 2, 3, 4];

let names: string[] = [
    "Alice",
    "Bob",
    "Charlie"
];

The syntax number[] means an array containing numbers.

Similarly, string[] represents an array containing strings.

9. Objects

JavaScript

const student = {
    name: "Alice",
    age: 20,
    active: true
};

TypeScript

const student: {
    name: string;
    age: number;
    active: boolean;
} = {
    name: "Alice",
    age: 20,
    active: true
};

TypeScript allows us to explicitly define the structure and types of an object.

10. Interfaces

TypeScript provides interfaces for describing the structure that an object should follow. 

interface Student {
    name: string;
    age: number;
    active: boolean;
}

We can then use the interface as the type of an object. 

const student: Student = {
    name: "Alice",
    age: 20,
    active: true
};
Interface idea: An interface defines what properties an object should have and what types those properties should use.

11. Optional Properties

TypeScript allows a property to be optional using ?. 

interface Student {
    name: string;
    age: number;
    email?: string;
}

The email property may exist, but it is not required. 

const student1: Student = {
    name: "Alice",
    age: 20
};

const student2: Student = {
    name: "Bob",
    age: 21,
    email: "bob@example.com"
};

12. Union Types

TypeScript can allow a variable to contain more than one specific type using a union type. 

let id: number | string;

id = 123;
id = "ABC123";

The | symbol means "or".

number | string means that the value can be either a number or a string.

13. Function Types

TypeScript can also describe the type of a function. 

let operation: (a: number, b: number) => number;

operation = function(a, b) {
    return a + b;
};

This means that operation must be a function that:

  • receives two numbers;
  • returns a number.

14. Classes

Both JavaScript and TypeScript support classes, but TypeScript allows their properties and methods to be explicitly typed.

JavaScript

class Student {
    constructor(name, age) {
        this.name = name;
        this.age = age;
    }

    introduce() {
        return `I am ${this.name}`;
    }
}

TypeScript

class Student {
    name: string;
    age: number;

    constructor(name: string, age: number) {
        this.name = name;
        this.age = age;
    }

    introduce(): string {
        return `I am ${this.name}`;
    }
}

15. Access Modifiers

TypeScript also provides access modifiers such as public, private, and protected. 

class Student {
    public name: string;
    private age: number;

    constructor(name: string, age: number) {
        this.name = name;
        this.age = age;
    }
}

These modifiers control how class properties and methods can be accessed.

16. Error Detection

JavaScript

function add(a, b) {
    return a + b;
}

add(10, "hello");

JavaScript permits the operation, although the result may not be what the programmer intended.

TypeScript

function add(a: number, b: number): number {
    return a + b;
}

add(10, "hello");

TypeScript can detect that the second argument does not match the declared type before the program runs.

TypeScript does not eliminate all possible errors. It primarily provides compile-time/static checking for the type-related problems that its type system can detect.

18. Node.js

Node.js is a JavaScript runtime that allows JavaScript to run outside of the browser.

Node.js will be covered later when studying backend development.

For now, the important idea is:

TypeScript → JavaScript → Browser or Node.js

19. TypeScript Compilation

TypeScript source code is processed by the TypeScript compiler (tsc), which checks the code and produces JavaScript. 

example.ts
     ↓
TypeScript Compiler
     ↓
example.js
     ↓
Browser / Node.js

The browser executes the resulting JavaScript rather than the original TypeScript type annotations.

20. Main Goal of TypeScript

The main goal of TypeScript is not simply to make JavaScript "more strict." Its type system provides tools for making programs easier to understand, maintain, refactor, and analyze, particularly as applications become larger.

Core idea:

JavaScript provides flexibility.
TypeScript adds static type information and tooling on top of JavaScript.

21. Key Points to Remember

  • TypeScript is a superset of JavaScript.
  • Valid JavaScript is generally valid TypeScript.
  • TypeScript adds static typing and other language features.
  • TypeScript code is normally compiled/transpiled into JavaScript before execution.
  • Browsers execute JavaScript, not TypeScript type annotations.
  • JavaScript is dynamically typed.
  • TypeScript provides static type checking.
  • TypeScript can detect many type-related errors before runtime.
  • Type annotations use the syntax variable: type.
  • Function parameters and return values can be typed.
  • Interfaces can describe object structures.
  • TypeScript supports union types, optional properties, generics, access modifiers, and other features.
