Unit 1 — Introduction

Unit 1: Introduction to Web Applications

Fundamental concepts of the Internet, Web, protocols, servers, browsers, and Web technologies.

1. Why Are There So Many Web Pages?

Web Applications

Modern applications can be distributed across different systems and services. This makes them easier to maintain, update, and scale.

Version control and deployment systems make it possible to manage different versions of an application. Some systems may also support returning to a previous version or state.

Testing and Standardization

Testing is an important part of software and Web engineering. Standardized interfaces and design patterns provide reusable approaches for developing software.

2. The Internet and the World Wide Web

The Internet is a global network based on a collection of communication protocols.

The Internet and the World Wide Web (WWW) are not the same thing. The Internet is the underlying network infrastructure, while the Web is a service that operates over the Internet.

In the early years of the Web, many websites used www as part of their domain name. Today, using www is optional.

The physical and networking foundations of the Internet have roots in military research, while many protocols and technologies were developed through scientific and academic research.

The Internet supports much more than Web applications. It also enables email, voice communication, video communication, file transfer, and many other networked services.

3. Historical Development

1969 - ARPANET
ARPANET became one of the first operational packet-switched computer networks. An early connection was established between UCLA and the Stanford Research Institute.
1974 - TCP/IP
The foundations of TCP/IP were publicly described in research by Vint Cerf and Bob Kahn. TCP/IP later became the core protocol suite of the Internet.
1989 - World Wide Web
Tim Berners-Lee proposed the World Wide Web at CERN and developed fundamental Web technologies including HTML, HTTP, and URLs.
1993 - Mosaic
Mosaic became an influential graphical Web browser and helped popularize the World Wide Web.
1994 - Netscape
Netscape became an important Web browser during the early commercial development of the Web.
2004 - Facebook
Facebook was launched and became an example of a large-scale Web application and social networking service.
2007 - iPhone
Apple introduced the first iPhone, contributing to the growth of mobile Internet access and mobile Web applications.
2022 - Billions of Internet Users
By 2022, Internet use had reached several billion people worldwide.

Interesting Fact

Some Web browsers can operate through a command-line interface instead of a graphical interface.

The First Web Browser and the World Wide Web

One common source of confusion is that WorldWideWeb was the name of the first Web browser, while the World Wide Web is the Web system itself.

What happened?

In 1989, Tim Berners-Lee proposed the World Wide Web at CERN. He designed a system for sharing information between computers using the Internet.

The Web was built using several important technologies:

  • HTTP: protocol used for communication between Web clients and servers.
  • URL: identifies and locates a resource on the Web.
  • HTML: language used to structure Web documents.
  • Web browser: software that retrieves and displays Web resources.

WorldWideWeb Browser

In 1990, Tim Berners-Lee created the first Web browser, called WorldWideWeb. It was both a browser and an editor for Web documents.

Therefore, when we ask for the first Web browser, the answer is WorldWideWeb (1990). This should not be confused with the World Wide Web, which is the system that the browser accesses.

How Does the Browser Find a Server?

The browser does not simply determine whether a computer is a server. Instead, it uses a URL to identify where a resource is located and then communicates with the appropriate server using HTTP.

HTML describes the structure of the document that the browser receives. The browser interprets the HTML and displays the content to the user.

Important Distinction

  • World Wide Web: the Web system/service.
  • WorldWideWeb: the first Web browser/editor.
  • HTML: structures Web documents.
  • HTTP: enables communication between clients and servers.
  • URL: identifies or locates a Web resource.
  • Mosaic (1993): an influential graphical browser that helped popularize the Web; it was not the first browser.

4. Networking Technologies

Wireless protocols became an important development in computer networking. Fiber-optic communication and other networking technologies later increased network capacity and speed.

5. Web Pages and Web Applications

Web Pages

A traditional Web page can contain mostly static content delivered by a Web server and displayed by a browser.

Web Applications

Web applications provide dynamic functionality. Users can interact with forms, databases, authentication systems, APIs, and other services.

Modern applications are frequently offered through subscription-based business models. Applications also need to be configurable and maintainable while generating value or revenue.

User Input and Validation

Web applications allow users to enter information into fields and forms. Developers must validate data received from users because input cannot automatically be assumed to be valid or safe.

6. Servers and Public IP Addresses

To make a Web application available on the Internet, it must run on a server that can receive network requests. A publicly accessible server normally needs a public IP address or another mechanism that makes it reachable from the Internet.

Devices can dynamically join and leave networks. Web applications can also reduce the need for traditional user manuals because interfaces can guide users through tasks directly.

7. Organizations and Internet Standards

IETF

The Internet Engineering Task Force (IETF) develops and maintains Internet standards and protocols.

ICANN

The Internet Corporation for Assigned Names and Numbers (ICANN) coordinates important aspects of Internet identifiers, including domain names and the Domain Name System.

W3C

The World Wide Web Consortium (W3C) develops Web standards and recommendations.

Domain names can have different values depending on length, memorability, demand, and other factors. Short domains are often valuable, but shorter does not universally mean more expensive.

8. Layered Network Architecture

Network communication is commonly explained using layered architectures. The OSI model contains seven conceptual layers.

The TCP/IP model is commonly represented using four layers:

  1. Application Layer
  2. Transport Layer
  3. Internet or Network Layer
  4. Network Access or Link Layer

9. HTTP and Transport Protocols

HTTP

HTTP stands for Hypertext Transfer Protocol. It is commonly used for communication between Web clients and Web servers.

Common HTTP methods include:

  • GET - retrieve a resource.
  • POST - submit data or request processing.
  • PUT - create or replace a resource at a specified location.

TCP and UDP

TCP and UDP are transport-layer protocols. TCP provides reliable, ordered delivery. UDP has lower overhead and does not provide the same delivery guarantees. Some real-time applications can use UDP when low latency is important.

10. IP Addresses

Network communication uses IP addresses to identify network interfaces and hosts. Two major versions are IPv4 and IPv6.

IPv4

IPv4 uses 32-bit addresses. Its address space became insufficient for the long-term growth of the Internet, contributing to the development and deployment of IPv6.

IPv6

IPv6 uses 128-bit addresses.

2128 ≈ 3.4 × 1038 possible addresses

Application logs can contain the source IP associated with a request. This can support security, logging, and access control, although an IP address alone does not reliably identify a specific person.

12. HTTPS and Encryption

HTTPS is HTTP transmitted through a secure TLS connection. It encrypts communication between the client and server and provides mechanisms for authentication and integrity.

Public-key cryptography uses a public key and a private key. Modern HTTPS uses several cryptographic mechanisms during the TLS handshake and subsequent encrypted communication.

13. Web Servers

A Web server is software that listens for Web requests and returns Web resources or responses.

  • Apache HTTP Server
  • Nginx
  • Microsoft Internet Information Services (IIS)

How Can We Make a Server?

A basic Web server can be created by installing server software, configuring it to listen on a port, and making the required resources accessible to clients.

14. Application Servers

An application server provides an environment in which server-side applications can run. Depending on the technology, it may provide lifecycle management, security, database connectivity, and communication services.

  • Apache
  • GlassFish

15. Web Browsers

A Web browser fetches and displays documents and other resources from Web servers.

  • Mozilla Firefox
  • Microsoft Edge
  • Apple Safari
  • Google Chrome
  • Opera

Developer tip: Applications should be tested in different browsers because developers cannot assume which browser or platform users will choose.

16. DNS - Domain Name System

The Domain Name System (DNS) is a distributed system that maps domain names to IP addresses and provides other information about Internet resources.

When a user enters a domain name, DNS can resolve that name to an IP address so that the client can communicate with the appropriate server.

17. URLs

A URL (Uniform Resource Locator) identifies the location and access method of a resource on the Web.

Basic Request Process

  1. The browser interprets the URL.
  2. The domain name may be resolved through DNS.
  3. The browser connects to the appropriate server and port.
  4. The browser sends an HTTP request, such as GET.
  5. The server processes the request.
  6. The server sends a response.
  7. The browser processes and displays the returned resource.

18. HTTP Headers and Requests

HTTP requests and responses contain headers that provide metadata about the communication. They also contain the information required to process the request or response.

Postman can be used to send HTTP requests, inspect responses, and test APIs.

20. MIME Types

MIME stands for Multipurpose Internet Mail Extensions. MIME types, also called media types, describe the format of data transferred over a network.

  • text/html
  • text/plain
  • image/jpeg
  • video/quicktime
  • application/pdf
  • application/octet-stream

21. Web Languages

HTML

HTML is a markup language used to structure Web documents.

CSS

CSS is a stylesheet language used to define the presentation and appearance of HTML documents.

PHP

PHP is a server-side programming language widely used for Web development. WordPress and Moodle are examples of platforms built with PHP. Early versions of Facebook also used PHP.

JavaScript

JavaScript is a programming language commonly executed by Web browsers. It allows developers to create interactive and dynamic functionality.

TypeScript

TypeScript is a programming language and a statically typed superset of JavaScript. TypeScript code is normally transpiled into JavaScript before execution in a browser or another JavaScript runtime.

22. Data Representation and Web Technologies

XML

XML is a markup language designed to represent structured data.

JSON

JSON is a lightweight data-interchange format widely used by APIs and Web applications.

AJAX

AJAX refers to techniques for making asynchronous requests from a Web page to a server and updating parts of the page without necessarily reloading the entire document. Modern implementations commonly use the Fetch API or XMLHttpRequest and frequently exchange JSON.

23. Key Concepts

  • The Internet is the network; the Web is a service that operates over it.
  • DNS maps domain names to IP addresses.
  • IP addresses identify network interfaces or hosts.
  • Ports identify services on a host.
  • HTTP is used for Web communication.
  • HTTPS provides HTTP communication through a secure TLS connection.
  • Web servers handle Web requests and return resources or responses.
  • Browsers request and display Web resources.
  • HTML structures content.
  • CSS styles content.
  • JavaScript provides programming and interactivity.
  • TypeScript adds static typing and other language features to JavaScript.
  • XML and JSON represent and exchange structured data.
  • Developers must validate user input and test applications across browsers.
