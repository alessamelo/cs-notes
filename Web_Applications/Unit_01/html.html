HTML

Date: August 18, 2026

What is HTML?

HTML stands for HyperText Markup Language. It is a markup language used to structure and describe documents on the World Wide Web.

  • HTML is not a programming language.
  • HTML is a markup language.
  • It is used to create and structure documents displayed on the web.
  • HTML documents are normally stored using the .html extension.

Other technologies such as PHP can generate HTML dynamically. The browser ultimately receives and interprets the resulting HTML document.

Platform Independence

HTML is platform independent. HTML documents can be accessed from systems such as Windows, Linux, Android, and iOS, provided that an appropriate browser or application is available.

Platform independence does not automatically mean that a webpage will look identical on every device. Responsive and adaptive design techniques are used to make webpages work appropriately across different screen sizes and devices.

HTML Documents and Elements

HTML uses elements to organize the content of a document. Common elements include headings, paragraphs, lists, tables, images, links, and forms.

HTML5 separates document structure from presentation. Many presentation attributes that were previously written directly in HTML are now handled using CSS.

Some older HTML attributes are deprecated and should not be used in modern HTML.

How HTML Works

HTML documents are interpreted by a web browser. The browser parses the HTML and uses its structure to display text, images, links, forms, and other content.

HTML can also contain hyperlinks, which allow users to navigate from one document or section to another.

Plain Text

Plain text refers to text without markup or specific formatting. It can be read directly as text without requiring a particular document structure or presentation format.

HTML Terminology

HTML Editor

An HTML editor is a program used to create and edit HTML files. Almost any text editor can be used to write HTML, including simple text editors and specialized code editors.

Browser

A web browser is software that parses HTML documents and renders their content as a webpage. It can also process CSS, JavaScript, images, audio, video, and other web resources.

Tags

HTML uses tags to define the structure of elements in a document. Tags are written using angle brackets. 

<html>

HTML tags are generally written in lowercase as a best practice. HTML itself is not case-sensitive for tag names, but consistent lowercase syntax is recommended.

Paired Elements

Most HTML elements have an opening tag and a closing tag. 

<p>This is a paragraph.</p>

The opening tag is <p> and the closing tag is </p>.

Void Elements

Some HTML elements do not have closing tags. These are commonly called void elements. 

<img src="image.jpg" alt="Example">

<br>

<hr>

<input type="text">

In HTML5, the slash in forms such as <br /> is optional. The modern HTML syntax is commonly written as <br>.

Attributes

An attribute provides additional information about an HTML element. Attributes are written inside the opening tag. 

<img src="photo.jpg" alt="A photograph">

In this example:

  • src specifies the image location.
  • alt provides alternative text for the image.

Attributes generally follow the form: 

attribute="value"

DTD and DOCTYPE

Document Type Declaration

A document type declaration tells the browser which HTML standard the document is intended to use.

Modern HTML documents normally begin with: 

<!DOCTYPE html>

This declaration activates standards mode in modern browsers.

Historically, HTML used more complex DTD (Document Type Definition) declarations to define the structure and rules of a document. HTML5 simplified the declaration to the form shown above.

Structure of an HTML Document

A basic HTML document can be structured as follows: 

<!DOCTYPE html>

<html lang="en">

    <head>
        <title>Page Title</title>
    </head>

    <body>

        <h1>Page Heading</h1>
        <p>Page content.</p>

    </body>

</html>

<html>

The <html> element is the root element of an HTML document. It contains the document's <head> and <body>.

The lang attribute can be used to specify the primary language of the document. 

<html lang="en">

<head>

The <head> contains information and resources associated with the document that are not normally displayed as the main page content.

It can contain elements such as:

  • <title>
  • <meta>
  • <link>
  • <style>
  • <script>

<title>

<title>My Webpage</title>

The title is displayed in the browser tab and is also used by browsers and search engines to identify the document.

<body>

The <body> contains the main content of the webpage, including text, headings, images, links, tables, forms, and other visible or interactive content.

Ways to Open an HTML Document

Opening a File Locally

An HTML document can be opened directly from the local filesystem using a web browser. 

file:///path/to/index.html

In this situation, the browser loads the document directly from the filesystem rather than requesting it from an HTTP web server.

Using a Web Server

HTML files can also be served through a web server such as Apache. In this case, the browser makes an HTTP or HTTPS request to the server, and the server returns the requested resource.

Apache

Apache HTTP Server is a web server that can receive HTTP requests and serve files such as HTML documents, images, CSS, and other resources.

Apache can also be configured to host multiple websites on the same server using Virtual Hosts.

HTTP and HTTPS

HTTP is a protocol used for communication between web clients and servers.

HTTPS is HTTP transmitted over an encrypted TLS connection. A server requires an appropriate certificate and private key to provide HTTPS.

Apache Configuration

The exact configuration directory depends on the operating system and Apache installation.

Common Linux Locations

  • Debian/Ubuntu commonly use /etc/apache2/.
  • RHEL/CentOS/Fedora-based systems commonly use /etc/httpd/.

HTTP Virtual Host

<VirtualHost *:80>
    ServerName webapp.yachaytech.edu.ec

    DocumentRoot /home/webapp

    ErrorLog /var/log/apache2/webapp-error.log
</VirtualHost>

Important directives include:

  • <VirtualHost *:80> defines a virtual host listening on HTTP port 80.
  • ServerName specifies the hostname associated with the site.
  • DocumentRoot specifies the directory containing the website's files.
  • ErrorLog specifies where Apache should record errors.

HTTPS Virtual Host

<VirtualHost *:443>
    ServerName webapp.yachaytech.edu.ec

    DocumentRoot /home/webapp

    SSLEngine on
    SSLCertificateFile /path/to/certificate.crt
    SSLCertificateKeyFile /path/to/private.key

    ErrorLog /var/log/apache2/webapp-ssl-error.log
</VirtualHost>

Port 443 is commonly used for HTTPS. The exact Apache directives and certificate configuration depend on the operating system and Apache version.

Redirecting HTTP to HTTPS

<VirtualHost *:80>
    ServerName webapp.yachaytech.edu.ec

    Redirect permanent / https://webapp.yachaytech.edu.ec/
</VirtualHost>

This configuration redirects requests made using HTTP to the HTTPS version of the website.

Index Files

When a user requests a directory without specifying a particular file, the web server can look for a default document.

A common default document is: 

index.html

For example, requesting: 

https://example.com/

may cause the server to look for: 

index.html

The exact default file is determined by the server configuration.

Testing a Server Without DNS

During development, a hostname can be mapped to an IP address locally using the operating system's hosts file. This allows a domain name to resolve to a test server without requiring public DNS configuration.

For example, a hosts file can contain: 

192.168.1.100    webapp.example.local

The appropriate IP address depends on where the server is running. For a local network test, this would commonly be the server's local network IP rather than its public IP.

Self-Signed Certificates

A self-signed certificate is a certificate generated and signed by the server or developer rather than by a publicly trusted Certificate Authority.

Self-signed certificates can be useful for development and testing, but browsers will normally display a security warning because the certificate is not trusted by a public Certificate Authority.

For production websites, certificates issued by a trusted Certificate Authority are normally used.

Viewing the HTML Source of a Website

Browsers provide ways to inspect the HTML source of a webpage. For example, a browser may support: 

view-source:https://yachaytech.edu.ec

This allows the user to view the HTML source received by the browser. It does not necessarily show every piece of code used by the server to generate the page, because server-side code is executed before the resulting HTML is sent to the browser.

Deprecated HTML Attributes

Older versions of HTML included attributes that were used to control presentation directly from HTML. Modern HTML separates structure from presentation and uses CSS for visual styling.

Examples of deprecated or obsolete presentation attributes include:

  • bgcolor
  • text
  • background
  • align
  • border for presentation purposes
  • cellpadding
  • cellspacing
  • font color and font size attributes
  • face for specifying fonts

These presentation concerns should generally be handled using CSS.

Important Concepts to Remember

  • HTML: describes the structure and meaning of web content.
  • CSS: controls presentation and visual appearance.
  • JavaScript: provides programming and dynamic behavior in the browser.
  • Browser: parses and renders HTML and other web resources.
  • Web server: receives requests and provides resources to clients.
  • HTTP/HTTPS: protocols used for communication between clients and servers.
  • DNS: translates domain names into IP addresses.
  • Apache: a web server that can serve websites and applications.

Semantic HTML

Semantic HTML is mainly concerned with the purpose and meaning of the content, rather than simply how the content looks.

Semantic elements communicate what a particular part of the webpage represents. They allow browsers, assistive technologies, and search engines to better understand the structure and meaning of the content.

Common Semantic Elements

<header>

Contains introductory content for a webpage or a particular section. It can contain elements such as headings, logos, or introductory information. 

<header>
    <h1>My Portfolio</h1>
    <p>Welcome to my website.</p>
</header>

<nav>

Represents a section containing navigation links. 

<nav>
    <a href="index.html">Home</a>
    <a href="about.html">About</a>
    <a href="projects.html">Projects</a>
</nav>

<main>

Contains the main content of the webpage. A document should normally have only one <main> element. 

<main>
    <h2>My Projects</h2>
    <p>These are my current projects.</p>
</main>

<section>

Represents a thematic grouping of related content. A section commonly has its own heading. 

<section>
    <h2>Programming</h2>
    <p>My programming projects and experience.</p>
</section>

<article>

Represents independent or self-contained content that could potentially be distributed or reused independently from the rest of the page.

Examples include blog posts, news articles, forum posts, or individual publications. 

<article>
    <h2>My Latest Project</h2>
    <p>Description of the project...</p>
</article>

<footer>

Represents the closing or footer content of a webpage or section. It can contain information such as author details, copyright information, contact information, or additional links. 

<footer>
    <p>Copyright 2026</p>
</footer>

Why Use Semantic HTML?

  • Understandability: makes the structure and purpose of the document easier to understand.
  • Accessibility: helps assistive technologies such as screen readers understand the structure of the page.
  • Search engines: provides additional information about the structure and meaning of webpage content.
  • Maintainability: makes the HTML code easier for developers to understand and maintain.

Semantic HTML and Visual Appearance

Semantic elements do not exist primarily to make a webpage look different. Their purpose is to communicate the meaning and role of the content.

For example, these elements may have different default browser styles, but their main value comes from what they represent: 

<header>
<nav>
<main>
<section>
<article>
<footer>

CSS is responsible for controlling the visual appearance of these elements.

Semantic HTML Is Not Just Code Organization

Semantic HTML should not be confused with simply organizing source code to make it easier for a developer to read.

Semantic elements give content a meaningful role that can be interpreted by browsers, assistive technologies, search engines, and other tools.

For example, using: 

<nav>
    <a href="about.html">About</a>
</nav>

communicates that the links represent a navigation section. Simply using a generic <div> around the same links does not provide that same semantic meaning.

Relative and Absolute Resource Paths

Images, stylesheets, scripts, and other resources can be referenced using either relative or absolute URLs.

Relative URL

<img src="images/photo.jpg" alt="Photo">

A relative URL specifies the location of a resource relative to the current document.

Absolute URL

<img src="https://images.example.com/photo.jpg" alt="Photo">

An absolute URL specifies the complete location of a resource, including its protocol and domain.

Why Use an Absolute URL?

In some situations, using an absolute URL can be useful when a resource is intentionally hosted on a different server or domain.

For example, a website could keep its images on a dedicated image server: 

<img src="https://images.example.com/photo.jpg" alt="Photo">

The main website could then be moved to another server without necessarily moving the image resources, because the images continue to be referenced from their separate server.

This can be useful when resources such as images, videos, or other files are intentionally hosted separately from the main web server.
