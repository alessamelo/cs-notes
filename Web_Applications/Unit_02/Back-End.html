MVC: Model-View-Controller

MVC stands for Model-View-Controller. It is a software architectural pattern commonly used to organize web applications.

Model

The model is responsible for the application's data and the logic used to handle that data. It represents and manages the information used by the application.

View

The view is the front-end, or the part of the application that the user sees and interacts with. It represents the user interface, such as a web page displayed in the browser.

Controller

The controller handles user input and interactions, including buttons, forms, and other interface actions.

The controller captures user actions, processes them, and communicates with the model. Changes in the model can then be reflected in the view.

An update does not necessarily mean a database update. It can simply mean a change in the application's state or in what is displayed in the user interface.

In a web application, the controller can be closely related to what we expose through an API, because it receives requests, processes them, and determines what response should be returned.

MVC in Web Applications

In the Web Applications course, we developed a web application that could potentially be transformed into a mobile application. In this type of design, the controller is important because it separates the application's logic from the interface and manages communication between the different parts of the system.

Monolithic Architecture

A monolithic system is a system in which the different components of the application are contained and developed as a single unit. The front end, application logic, and other components may be deployed together.

Modern applications can instead separate different responsibilities into different services or servers. For example, a project could have separate servers or services for the front end, database, and application logic.

Frontend and Backend

Frontend

The frontend is the part of an application that the user sees and interacts with. In a web application, it is responsible for displaying content in the browser and interacting with the backend through requests and responses.

The frontend can attend to user interactions and webpage-related requests, display information in the browser, and communicate with backend services.

Backend

The backend contains the application's server-side logic. It is the core of the application and can include application logic, web-server functionality, file-system operations, database access, authentication, and APIs.

Backend development refers to the development of server-side logic that powers websites and applications behind the scenes. It includes the code and configuration needed to build and operate the database, server, and application logic, from database migrations and API integration to configuring the server-side technologies that make a website or application function.

A backend web developer may therefore be responsible for building the server-side components needed to get a project running.

Web Servers

A traditional web application requires a web server to receive HTTP requests and return responses.

However, it is possible to design systems where some requests do not need to go through a traditional web server. Different components can communicate directly through other protocols or services depending on the architecture.

It is also possible to use multiple servers or services for different parts of a project, such as:

  • A frontend server or service
  • A database server
  • An application-logic server

What Is the Backend?

The backend is the logic of the application and represents the core functionality that operates behind the user interface.

A Web API acts as a communication layer between the frontend and backend. The frontend makes API calls using defined methods, and the backend processes those requests and returns data or other responses.

Data can be transmitted from the backend to the frontend using formats such as JSON.

The backend therefore provides the services and application logic that drive the functionality of the system.

APIs

An API (Application Programming Interface) defines how different software components communicate with each other.

An API can provide a structured way for a frontend or another application to access data and functionality provided by the backend.

The API can therefore act as a layer through which data is exchanged between a database-backed application and the software accessing that application.

For a project, it is generally recommended to construct an API when multiple clients or components may need to access the same backend functionality. For example, a web application and a mobile application can consume the same API.

Frontend Communication

AJAX

AJAX allows web pages to communicate with a server asynchronously without requiring the entire page to reload after every request.

Modern web applications commonly use the Fetch API for this type of communication. Fetch allows the frontend to send requests to a server asynchronously and process the response when it becomes available.

Axios

Axios is another commonly used JavaScript library for making HTTP requests from frontend applications and other JavaScript environments.

Traditional direct HTTP request techniques still exist, but modern applications commonly use higher-level APIs and libraries such as Fetch or Axios.

Backend Frameworks

Backend frameworks are software frameworks that provide structures, libraries, and tools for developing server-side applications. They provide predefined mechanisms for handling common backend tasks, allowing developers to construct the structure of a web application more efficiently.

The framework provides both reusable functionality and an execution environment or structure in which the application's server-side logic operates.

How Many Backend Frameworks Are There?

There is no official number of backend frameworks. Depending on how frameworks are counted, there can be approximately 50–100 frameworks with established communities, around 25–40 with significant adoption, and approximately 15–20 that are widely relevant in the industry.

These numbers are approximate because the ecosystem changes over time and the definition of what qualifies as a framework varies.

Node.js

Node.js is not a backend framework. It is a JavaScript runtime environment that allows JavaScript code to run outside the web browser, including on servers.

Frameworks such as Express, NestJS, and Fastify run on top of Node.js.

One important advantage of Node.js is that it allows both the frontend and backend to be developed using JavaScript.

Backend Programming Languages

C++

C++ combines many of the features of C with object-oriented programming features such as classes. It is a relatively low-level programming language and provides direct control over system resources.

C#

C# is widely used in Microsoft environments and is commonly used for Windows-based server applications with ASP.NET.

Java

Java is a general-purpose, object-oriented programming language designed with cross-platform compatibility in mind. Programs can run on systems that have a compatible Java Virtual Machine (JVM).

Java has a relatively significant learning curve compared with some other languages.

JavaScript and Node.js

JavaScript has traditionally been considered a frontend language because it runs in web browsers. The introduction of Node.js made it possible to execute JavaScript on the server.

This allows both the frontend and backend of an application to be developed using JavaScript.

PHP

PHP is one of the most widely used backend languages for web development. It appeared around the early development of dynamic web pages and can be embedded into HTML to generate content dynamically.

PHP has received criticism related to aspects such as its historical type system, performance, and security practices. However, the language has evolved considerably over time and remains widely used.

PHP supports object-oriented programming and is commonly used for web applications. WordPress is primarily written in PHP, and Moodle is also written in PHP.

Python

Python is a general-purpose programming language with an extensive ecosystem of libraries. For backend development, Python provides high programmer productivity through its relatively simple syntax and concise code.

Some Python libraries implement performance-critical functionality in languages such as C, C++, or Fortran while exposing those capabilities through Python. This allows developers to combine Python's productivity with native-code performance for computationally intensive operations.

Perl

Perl became popular during the 1990s, particularly in Linux and Unix environments. Its strengths include text manipulation, scripting, and log processing. It is useful for writing scripts that perform text-processing and system-administration tasks.

Scala

Scala supports both object-oriented programming and functional programming. It runs on the Java Virtual Machine and can interact with Java libraries.

Ruby

Ruby is a dynamically typed, general-purpose programming language designed with programmer productivity in mind. It supports procedural, functional, and object-oriented programming paradigms.

Ruby is particularly associated with web development through frameworks such as Ruby on Rails.

Backend Technologies

Backend development can involve several different technologies and responsibilities, including:

  • Server-side programming languages
  • Backend frameworks
  • Web servers
  • Databases
  • APIs
  • Authentication and authorization
  • Security
  • File-system operations
  • Server configuration and administration
  • Database migrations

Skills Needed for Backend Developers

A backend developer should have a basic understanding of frontend technologies such as HTML, JavaScript, and CSS.

Backend developers should have working knowledge of backend development, server configuration, server administration, and database management.

Important Skills

  • Basic understanding of frontend technologies such as HTML, JavaScript, and CSS
  • Working knowledge of backend development
  • Configuration, administration, and management of databases and servers
  • Knowledge of server-side programming languages
  • Knowledge of database technologies
  • Linux knowledge
  • Security and authentication best practices
  • Experience writing RESTful APIs

RESTful APIs

A RESTful API is an API designed according to the principles of REST (Representational State Transfer). It provides structured endpoints through which clients can interact with resources provided by a backend.

RESTful APIs are commonly used to connect frontend applications, mobile applications, and other software with backend services.
