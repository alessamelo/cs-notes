1. Introduction to Databases

Applications are generally connected with a database or many databases.

Database: A database is a collection of organized data, information and records. It is software that stores information related to a particular activity or purpose.

Examples:

  • Bank
  • Hospital
  • University
  • Internet

A database includes tools to help organize and maintain the data. A database design engineer must know and be able to use these tools in order to make the database efficient and accurate.

2. DBMS

DBMS stands for Database Management System.

A properly designed database allows information to be updated once, and all other occurrences of this information within the database will be updated automatically.

A principal requirement of any database system is the ability to generate, store and retrieve data efficiently.

The user can generate a question through an interrogation/query.

The general process can be represented as:

Data → Processing → Information → Reports / Decisions

Tools are used throughout this process.

3. SQL

SQL stands for Structured Query Language.

SQL is associated with structured databases.

4. Types of Databases

Structured Database

All information is saved in the same way.

Free-Form Database

A loose collection of information, such as those found on the World Wide Web.

Operational Database

A dynamic database that is used by an organization in its day-to-day operations.

Examples: electrical distribution and oil extraction databases.

Operational databases are used to collect, maintain, modify and delete data. Decisions can be taken during execution.

Analytical Database

A static database where data is rarely modified. It is often used to store and track historical data, make long-term projections and perform analysis.

Example: population census.

5. Database Models

Hierarchical Model

This model can be visualized as a parent-child relationship, wherein a child may only have one parent, but a parent can have several children.

Another way of looking at this model is as an inverted tree. The single table acts as the root of the inverted tree and the other tables act as branches.

Relational Model

The relational model is widely used until now.

  • Data is organized into tables.
  • Tables have primary keys.
  • Tables can have relationships between them.

Primary Key

A primary key identifies records in a table.

Index

Every database works with an index. The database only searches the index where the IDs are, making the process faster.

Foreign Key

A foreign key is a key that exists on the other side of a relationship.

The relational model was developed by E. F. Codd for IBM in the 1970s, partly to solve problems of earlier database models and to make databases less dependent on any particular application.

The terms include relations, attributes (columns) and domains.

Entity-Relationship Model

This model was introduced by Peter Chen in 1976. It is an abstract and conceptual representation of data.

Dimensional Model

A specialized adaptation using the relational model that is used to represent data in data warehouses.

A data warehouse is essentially storage of digital data of a company or organization.

Object-Relational Database

Object-oriented programming can be considered as a model of objects. An entity can be considered as a class. OOP has attributes and methods.

6. Database Design

Database design involves creating a database structure that satisfies the requirements of the application.

Important Design Objectives

  • Avoid duplicate data.
  • Determine what records are needed in files.
  • Design an appropriate database model.

Data Dependence

Data dependence deals with the mechanisms for changing database structure.

Good database design should ensure that it is relatively easy to make necessary modifications to the structure.

Data Redundancy

Data redundancy is one of the most common problems.

If data is replicated, when something is changed in one copy, it needs to be changed in the other copy.

Data Anomalies

Modification and deletion anomalies are related to data in one-to-many relationships.

8. Database Alternatives

MySQL

MySQL uses the ACID model:

  • Atomicity
  • Consistency
  • Isolation
  • Durability

It has more than 20 years of history and supports C++ and C.

When to use MySQL

It is suitable for applications that need a transactional SQL engine, including heavy-traffic websites or mission-critical applications.

It can be used for horizontal scalability, multi-master ACID transactions and applications that require a converged database.

MariaDB

MariaDB is designed to provide scalability and is similar to SQL. It uses InnoDB as the storage engine and is intended to provide good performance.

It is free but has commercial support.

Recommended when a multimodel database is needed.

PostgreSQL

PostgreSQL is an open-source relational database management system with good performance. It supports JSON and SQL relational querying.

It is compatible with C, Java, Python, Ruby and ODBC. It is compatible with Linux, Windows and Unix.

It offers support for data integrity.

Recommended when

  • A distributed database is used.
  • The system needs to handle millions of transactions.
  • A query planner is required.
  • The application needs disaster recovery and reliability features.
  • Active standby and PITR are required.

SQLite

SQLite is lightweight software written in C. The database is stored as a file, similar to a CSV file.

  • No setup or administration is required.
  • Small code footprint.
  • Easy to use.
  • Self-contained with zero dependencies.
  • Embedded database.

Recommended when

It can be used when there are limited hardware resources, such as:

  • Electronic devices
  • Cameras
  • Automobiles
  • Airplanes
  • Remote sensors
  • Game consoles
  • Drones

It works well as a database engine for websites with low to medium traffic.

MongoDB

MongoDB is a document-oriented database that offers scalability and flexibility.

It stores data in flexible JSON-like documents. Fields can differ between documents and the data structure can be modified.

Recommended when

  • A real-time view of data is required.
  • Real-time analytics are required.
  • Data collected from physical works needs to be analyzed.
  • Content needs to be stored and shared.
  • Features need to be built around flexible data.

Redis

Redis is an open-source, in-memory data structure store used as a cache database, streaming engine and message broker.

It is fast and supports data structures such as bitmaps, range queries, HyperLogLogs and streams.

Because it works in memory, it is usually used as a buffer. For example, it can store queries made to another database.

Recommended when

  • Memory caching is required.
  • Data latency needs to be reduced.
  • Load needs to be reduced on another database.
  • Session data needs to be stored.
  • High availability and persistence are required.
  • Real-time streaming is required.

9. ORM

ORM stands for Object-Relational Mapping.

ORM is a system for mapping objects to a database. It automates the transfer of data stored in relational database tables into objects commonly used in application code.

An Object-Relational Mapper maps a relational database system to objects.

The ORM is independent of which relational database system is used. From languages such as Python, PHP and JavaScript, developers can work with objects through the ORM and map them to the database.

Advantages of ORM

  • Generates database inserts and mappings.
  • Maps database attributes to object attributes.
  • Provides a high-level abstraction over a relational database.
  • Allows developers to write object-oriented code instead of SQL.
  • Supports CRUD operations.
  • Can work with database schemas using objects.

CRUD

  • Create
  • Read
  • Update
  • Delete

A class is relatively equivalent to a SQL table. An instance of the class is equivalent to a record in the table.

Developers can use the programming language they are comfortable with to work with a database instead of writing SQL statements or stored procedures.
